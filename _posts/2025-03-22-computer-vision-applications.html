Computer vision turns pixels into structured decisions: boxes, masks, poses, identities, or embeddings. The difficult engineering work sits between the model and the camera: data collection, annotation policy, domain shift, latency, calibration, and safe behavior when the scene is unfamiliar.

The vision pipeline

A production pipeline includes capture, decoding, resize and normalization, inference, post-processing, tracking, and an action policy. Every transformation affects the label space. A resize that changes aspect ratio, a color conversion mismatch, or a different camera exposure can degrade accuracy without changing model weights.

frame -> decode -> preprocess -> backbone -> task head
      -> confidence calibration -> NMS/tracking -> decision

Keep preprocessing versioned and test it with golden images. When data comes from video, split by scene, camera, and time rather than randomly splitting frames from the same sequence.

Modern architectures

CNN backbones provide strong local inductive bias and efficient feature pyramids. Vision Transformers tokenize patches and use self-attention to model global relationships. DETR-style detectors predict object queries and remove much of the hand-designed anchor machinery, while segmentation models combine image encoders with promptable or task-specific decoders.

Architecture choice is a constraint problem. Resolution, object size, memory bandwidth, batch size, and p99 latency often matter more than a small benchmark improvement. A two-stage coarse-to-fine pipeline can outperform a single oversized model when the scene is sparse.

Representation learning

Self-supervised learning uses unlabeled images. Contrastive learning aligns augmented views while separating unrelated samples; masked image modeling predicts hidden patch representations. These objectives can produce useful features when labels are expensive, but fine-tuning must test whether the representation learned camera or background shortcuts.

Augmentations should reflect valid changes in the domain. A horizontal flip may be harmless for generic objects but invalid for a medical or traffic sign task. Track label noise and ambiguous examples explicitly rather than forcing annotators into false certainty.

Evaluation

Detection should report precision-recall across IoU thresholds, small-object performance, false positives per image, and latency. Segmentation needs Dice or IoU plus boundary error and instance-level detection. For retrieval and embeddings, use recall@k under realistic distractors. Evaluate by camera, lighting, geography, object scale, and occlusion.

Confidence calibration matters when predictions trigger actions. An uncertain detector should defer, request another frame, or route to review. Average accuracy hides the tail of rare but costly scenes.

Edge deployment

Quantization, pruning, distillation, and compilation reduce memory and latency. INT8 calibration must include representative images and post-processing; a fast backbone is not useful if Python decoding or host-device copies dominate the path. Measure end-to-end p50 and p99 latency, energy, thermal throttling, and memory after a long-running session.

Monitor camera health, input distribution, confidence, tracking continuity, and drift. A model that cannot recognize that its sensor is covered should not silently emit normal predictions.
