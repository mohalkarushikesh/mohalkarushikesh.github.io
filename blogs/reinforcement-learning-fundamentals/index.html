Reinforcement Learning Fundamentals

A practical, in-depth guide to reinforcement learning: MDPs, value and policy methods, deep RL algorithms, and how RL now powers reasoning LLMs through RLHF, DPO, and GRPO.

May 05, 2025 · 11 min read · By reinforcement learningRLQ-learningpolicy gradient

Reinforcement Learning (RL) is a branch of machine learning focused on sequential decision-making. An agent interacts with an environment, taking actions to maximize cumulative rewards over time. Unlike supervised learning, RL does not rely on labeled data but instead learns from feedback in the form of rewards or penalties. What makes RL distinct — and difficult — is that feedback is often delayed, sparse, and evaluative rather than instructive: the environment tells you how good an action was, not what the correct action would have been.

RL is the study of learning to act: mapping situations to actions so as to maximize a long-run reward signal, under uncertainty and with delayed consequences.

Core Concepts

  • Agent and Environment: The agent is the learner or decision-maker; the environment is everything the agent interacts with and cannot directly control.
  • State, Action, Reward: At each step the agent observes a state s, selects an action a, and receives a scalar reward r plus a next state s'.
  • Policy (π): A mapping from states to actions (or to a probability distribution over actions). The policy is the agent's behavior; learning a good policy is the whole goal.
  • Return: The discounted sum of future rewards, G_t = r_t + γ r_{t+1} + γ^2 r_{t+2} + .... RL maximizes the expected return, not any single reward.
  • Discount Factor (γ): A value in [0, 1) that weights future rewards against immediate ones. Values near 1 make the agent farsighted; values near 0 make it myopic.
  • Value Functions and Q-functions: The state-value V(s) estimates expected return from a state; the action-value Q(s, a) estimates expected return from taking action a in state s and following the policy thereafter.
  • Exploration vs. Exploitation: The agent must balance trying new actions to discover better strategies (exploration) against using what it already knows to be good (exploitation).

The Markov Decision Process

Almost all of RL is formalized as a Markov Decision Process (MDP), defined by the tuple (S, A, P, R, γ): a set of states S, a set of actions A, transition dynamics P(s' | s, a), a reward function R(s, a), and a discount factor γ. The defining Markov property is that the future depends only on the current state, not on the full history — the state is a sufficient statistic.

The core objects satisfy the Bellman equations, which express value recursively in terms of the value of successor states. For the optimal action-value function:

Q*(s, a) = E[ r + γ * max_a' Q*(s', a') | s, a ]

This recursion is the engine behind nearly every value-based algorithm. When we know P and R, we can solve it exactly with dynamic programming (value iteration, policy iteration). When we do not — the usual case — we sample transitions and approximate the expectation, which is what Q-learning and its descendants do.

Value-Based vs. Policy-Based Learning

Model-free RL splits into two broad families that answer the control problem differently. Value-based methods learn Q(s, a) and derive a policy implicitly by acting greedily. Policy-based methods parameterize and optimize the policy directly. Actor-critic methods combine both: an actor proposes actions while a critic estimates value to reduce variance.

Property Value-Based (e.g. DQN) Policy-Based (e.g. PPO)
What is learned Action-value function Q(s, a) Policy π(a | s) directly
Action spaces Best for discrete actions Handles continuous actions naturally
Policy type Deterministic (greedy) Stochastic, differentiable
Sample efficiency Higher (off-policy, replay buffer) Lower (often on-policy)
Stability Can diverge with function approximation More stable, but high variance gradients

Popular Algorithms

Tabular Methods

For small, discrete state and action spaces, values can be stored exactly in a table. Q-learning is the canonical off-policy tabular algorithm; SARSA is its on-policy sibling. These are foundational: nearly every deep RL method is a function-approximation generalization of them.

Deep Q-Networks (DQN)

DQN (Mnih et al., 2015) replaced the Q-table with a neural network, enabling RL on high-dimensional inputs such as raw Atari pixels. Two tricks made it stable: an experience replay buffer that breaks correlation between consecutive samples, and a periodically updated target network that stabilizes the bootstrapped Bellman target. Later refinements — Double DQN, Dueling DQN, Prioritized Experience Replay, and the combined Rainbow agent — each addressed a specific source of bias or inefficiency.

Policy Gradient and Actor-Critic Methods

  • REINFORCE: The simplest policy gradient; scales the log-probability of actions by the observed return. Unbiased but high variance.
  • A2C / A3C: Actor-critic methods that use a learned value baseline (the advantage) to cut variance.
  • PPO (Proximal Policy Optimization): The workhorse of modern RL. It constrains each policy update with a clipped surrogate objective so the new policy stays close to the old one, giving robust, low-tuning training. PPO is the algorithm most commonly used to fine-tune large language models.
  • SAC (Soft Actor-Critic): An off-policy actor-critic that adds an entropy bonus to the objective, encouraging exploration and delivering strong sample efficiency on continuous-control tasks.
  • DDPG / TD3: Off-policy methods for continuous control; TD3 adds twin critics and delayed updates to curb overestimation.

Model-Based RL

Model-based methods learn (or are given) the environment dynamics and plan against them. MuZero (DeepMind) learns a latent dynamics model and plans with Monte Carlo Tree Search, mastering Go, chess, shogi, and Atari without being told the rules. Dreamer learns a world model and trains a policy inside imagined rollouts, dramatically improving sample efficiency.

A Worked Example: Q-Learning on Gridworld

To make the update concrete, consider tabular Q-learning. The agent maintains a table Q[s][a] and, after every transition (s, a, r, s'), nudges its estimate toward the bootstrapped target using a learning rate α:

Q[s][a] ← Q[s][a] + α * ( r + γ * max_a' Q[s'][a'] - Q[s][a] )

The bracketed quantity is the temporal-difference (TD) error — the gap between what we predicted and what we now estimate. A minimal training loop in Python:

import numpy as np

Q = np.zeros((n_states, n_actions))
alpha, gamma, epsilon = 0.1, 0.99, 0.1

for episode in range(num_episodes):
    s = env.reset()
    done = False
    while not done:
        # epsilon-greedy action selection
        if np.random.rand() < epsilon:
            a = np.random.randint(n_actions)   # explore
        else:
            a = int(np.argmax(Q[s]))           # exploit

        s_next, r, done = env.step(a)

        # temporal-difference update
        td_target = r + gamma * np.max(Q[s_next]) * (not done)
        Q[s][a] += alpha * (td_target - Q[s][a])

        s = s_next

Because Q-learning is off-policy, it learns the optimal greedy policy even while behaving with random exploration. Given enough visits to every state-action pair and a decaying learning rate, the table provably converges to Q*.

Exploration Strategies

How an agent explores often matters more than which update rule it uses. Common approaches:

Strategy Idea Trade-off
ε-greedy Act randomly with probability ε, greedily otherwise Simple; explores uniformly and inefficiently
Boltzmann / softmax Sample actions in proportion to their estimated value Focuses exploration but needs temperature tuning
Entropy regularization Reward the policy for staying stochastic (used in SAC, PPO) Smooth and differentiable; central to modern methods
Intrinsic / curiosity rewards Bonus for reaching novel or surprising states Helps with sparse rewards; can chase noise

RL for Language Models: RLHF, DPO, and GRPO

The most consequential recent application of RL is aligning and improving large language models. Because "helpfulness" has no closed-form reward, the field learns a reward from human judgments and optimizes against it.

RLHF (Reinforcement Learning from Human Feedback)

RLHF, popularized by InstructGPT and used across modern assistant models, has three stages: (1) supervised fine-tuning on demonstrations; (2) training a reward model from human preference comparisons between candidate responses; and (3) optimizing the policy against that reward model with PPO, while a KL penalty keeps the model from drifting too far from the supervised base. The KL term plays the same role as PPO's trust region — it prevents reward hacking and preserves fluency.

DPO (Direct Preference Optimization)

DPO (Rafailov et al., 2023) removed the separate reward model and the online RL loop entirely. It reformulates preference learning as a single classification-style loss on preferred vs. rejected responses, implicitly optimizing the same objective as RLHF. Because it is a stable supervised-style update, DPO is far simpler to run and has become a default for open-weight preference tuning. Variants such as IPO and KTO refine its loss and data assumptions.

GRPO and RL for Reasoning

The 2024-2025 wave of reasoning models brought RL back to the center. GRPO (Group Relative Policy Optimization), introduced in the DeepSeekMath work and used prominently in DeepSeek-R1, drops PPO's learned value critic. Instead it samples a group of responses per prompt and normalizes each response's reward against the group's mean and standard deviation to form the advantage — cutting memory and complexity while remaining stable. Crucially, for math and code the reward can be a simple, verifiable check (does the answer match, does the test pass), an approach often called RLVR — RL from Verifiable Rewards. This is how models are trained to produce long chains of thought that improve with more inference-time compute, the paradigm behind OpenAI's o-series and DeepSeek-R1.

Method Needs reward model? Online sampling? Typical use
PPO (RLHF) Yes Yes General alignment / helpfulness
DPO No (implicit) No (offline pairs) Simple, stable preference tuning
GRPO No critic; uses group baseline Yes Reasoning with verifiable rewards

Real-World Applications

  • Robotics: Autonomous navigation, dexterous manipulation, and motion planning, increasingly trained in simulation and transferred to hardware (sim-to-real).
  • Games: Mastering Go (AlphaGo), chess and shogi (AlphaZero, MuZero), and complex real-time games such as StarCraft II and Dota 2.
  • Operations: Dynamic resource allocation, inventory optimization, scheduling, and datacenter energy management.
  • Autonomous Vehicles: Learning and refining driving policies under varying, uncertain conditions.
  • Language and Reasoning Models: RLHF, DPO, and GRPO for alignment and for training chain-of-thought reasoning.
  • Recommendation and Ads: Long-horizon optimization of engagement and retention rather than single-click prediction.

Best Practices and Common Pitfalls

Effective RL systems require careful reward design, simulation before deployment, and monitoring for distribution shifts. Poorly specified rewards can lead to unintended behaviors, while realistic simulations ensure robust performance. A few hard-won lessons:

  • Reward hacking: Agents optimize the reward you wrote, not the goal you intended. Shape rewards carefully and watch for degenerate high-reward strategies.
  • Sparse rewards: When reward arrives only at success, learning stalls. Use reward shaping, curriculum learning, or intrinsic motivation.
  • Instability from bootstrapping: The "deadly triad" of function approximation, bootstrapping, and off-policy learning can cause divergence. Target networks, gradient clipping, and normalized advantages help.
  • Evaluation seeds and variance: RL results vary wildly across random seeds; always report across multiple seeds.
  • Simulate first: Train and stress-test in simulation, and validate sim-to-real transfer before touching physical systems.

Future Outlook

Future RL research focuses on sample efficiency, safe exploration, and scalability. Current algorithms often require millions of interactions to learn effectively, which is impractical in many real-world settings. Researchers are developing methods to reduce data requirements, leverage transfer learning, and integrate prior knowledge.

  • Sample Efficiency: Using model-based RL and offline datasets to reduce training interactions.
  • Offline RL: Learning entirely from logged data without live interaction — critical where exploration is costly or unsafe (healthcare, finance).
  • Safe Exploration: Ensuring agents avoid catastrophic actions during training and deployment.
  • Scalability: Applying RL to large-scale systems like smart grids, logistics, and healthcare.
  • RL from Verifiable Rewards: Scaling reasoning by rewarding checkable correctness in math, code, and tool use.
  • Integration with Other Paradigms: Combining RL with supervised learning, self-supervised learning, and generative models for richer capabilities, including agentic LLM systems that plan and use tools.


Reinforcement Learning is not just an algorithmic framework — it is a paradigm for building adaptive, intelligent agents that learn from experience, and it has become the training signal that turns capable models into aligned, reasoning ones.
